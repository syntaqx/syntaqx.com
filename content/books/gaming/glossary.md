Games borrow words from engine programming, networking, finance, consumer law and moderation, and vendors name the same thing differently: one platform's entitlement is another's license, ownership or item grant, and one engine's chunk is another's archive. Each entry here is one line and a link to where the volume explains it, or to the chapter that owns the idea when several touch it. The volume's own names (account, player profile, entitlement, item instance, wallet, match, penalty) are the ones in [The Core Data Model](/books/gaming/games-business#the-core-data-model).

## How Games Get Made

- **Account:** the publisher's identity for a person (`accounts`), the thing a login, linked platform, wallet or ban attaches to, across all of the publisher's games ([The Games Business](/books/gaming/games-business#the-core-data-model)).
- **Accumulator:** the elapsed time a fixed-step loop has yet to simulate; each frame adds the clamped frame time and the simulation consumes it in fixed `dt` steps ([Building Your Own Engine](/books/gaming/building-an-engine#fixed-and-variable-timesteps)).
- **Actor, component:** Unreal's object that can be placed in a level, and the units of behavior (with or without a transform) it is composed from ([The Engine Landscape](/books/gaming/engine-landscape#unreal-engine)).
- **Advance, recoupment:** publisher funding paid before release, usually in milestone tranches, and earned back (with any agreed markup) from the game's revenue before the developer is paid a royalty; the split usually shifts toward the developer once it is recouped ([The Games Business](/books/gaming/games-business#funding-and-deals)).
- **Archetype, chunk (ECS):** entities with the same set of components share an archetype, stored in fixed-size chunks (16 KiB in Unity) that hold one dense array per component type plus the entity IDs; not the same as a content chunk in patching ([Building Your Own Engine](/books/gaming/building-an-engine#objects-components-and-ecs)).
- **Audio mixer, mixer buffer:** the engine thread that mixes every playing sound into blocks ahead of the audio device under a hard real-time deadline; a missed block is an audible dropout, so nothing on that thread waits on a lock, allocates or touches the disk ([Building Your Own Engine](/books/gaming/building-an-engine#audio)).
- **Broadphase, narrowphase:** the two collision stages of a physics step: a cheap bounding-volume pass that finds pairs of bodies that might touch, then exact contact points, normals and depths for those pairs ([Building Your Own Engine](/books/gaming/building-an-engine#physics)).
- **Build:** the parts produced for one platform from one source revision (executable, shaders, cooked content, a manifest and symbols), recorded as a `builds` row that crashes, matches and tickets name ([Production Pipelines & Builds](/books/gaming/production-pipelines#what-a-build-is)).
- **Build farm, build graph:** a pool of machines running a build described as nodes with dependencies, such as Epic's BuildGraph scheduled by Horde, so independent steps run in parallel ([Production Pipelines & Builds](/books/gaming/production-pipelines#build-farms-and-ci)).
- **Build verification system (BVS):** Riot's automated test run on every new League build, about 5,500 cases in about 18 minutes, reporting within about an hour of check-in ([Production Pipelines & Builds](/books/gaming/production-pipelines#automated-testing-at-scale)).
- **Certification (cert):** the platform holder's test of a game or patch against its requirements before it can ship on a console; Microsoft publishes the Xbox Requirements (XRs), while Sony's (commonly called the TRC) and Nintendo's (its submission check is Lotcheck) are under NDA ([Production Pipelines & Builds](/books/gaming/production-pipelines#platform-certification)).
- **Cloud streaming:** running the game in a data center and streaming video to the player's device, which removes the install but adds input latency and its own licensing per service ([The Games Business](/books/gaming/games-business#platforms)).
- **Compliance QA, pre-cert:** running a platform holder's requirement test cases in-house against a build before submitting it to certification ([Production Pipelines & Builds](/books/gaming/production-pipelines#qa-and-playtesting)).
- **Cooking:** converting content from the engine's internal format to a platform-specific one (compressed textures, compiled shaders, editor-only fields stripped), cached by a hash of every input that can change the output ([Production Pipelines & Builds](/books/gaming/production-pipelines#assets-cooking-and-packaging)).
- **Determinism:** the simulation producing the same result from the same inputs; broken by wall clocks, floating point differences, iteration order, threads, uninitialized memory and unseeded randomness ([Building Your Own Engine](/books/gaming/building-an-engine#determinism); the netcode that depends on it is in [Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#what-determinism-requires)).
- **Developer, publisher, platform holder:** the studio that builds a game, the company that funds, markets and distributes it, and the company that runs the hardware or store and sets certification, fees and identity ([The Games Business](/books/gaming/games-business#who-makes-a-game)).
- **Engine:** the part of a game that isn't the game: the loop, renderer, physics, audio, networking, asset pipeline and editor, and the largest dependency a studio takes on ([The Engine Landscape](/books/gaming/engine-landscape#what-an-engine-gives-you)).
- **Entity component system (ECS):** a design where an entity is only an ID, components are plain data and systems are functions over every entity with a given set of components; Unity's Entities package (part of DOTS), Unreal's MassEntity and Bevy are examples ([Building Your Own Engine](/books/gaming/building-an-engine#objects-components-and-ecs)).
- **Fixed timestep:** advancing the simulation in equal `dt` steps whatever the frame rate, so results don't depend on hardware; a variable `dt` taken from the last frame makes physics differ between machines ([Building Your Own Engine](/books/gaming/building-an-engine#fixed-and-variable-timesteps)).
- **Frame budget:** the milliseconds a frame may take at a target rate (16.67 ms at 60 frames a second, 7.8125 ms for a 128-tick server), divided among subsystems with an owner for each ([Building Your Own Engine](/books/gaming/building-an-engine#the-frame-budget)).
- **Glyph budget, font fallback:** the set of characters a game's font atlases must hold within each platform's memory, and the ordered fallback fonts searched for characters one font lacks ([Production Pipelines & Builds](/books/gaming/production-pipelines#localization)).
- **Job system, work stealing:** work split into small jobs with declared reads, writes and dependencies, run by a pool of about one worker thread per core, where an idle worker takes jobs from another's queue ([Building Your Own Engine](/books/gaming/building-an-engine#threads-and-job-systems)).
- **Live service:** an operating model rather than a price, in which the game keeps changing after launch through patches, seasons, events and configuration, for years ([The Games Business](/books/gaming/games-business#five-ways-games-make-money)).
- **Localization (l10n), LQA:** adapting a game's text, assets and voice per language, as a pipeline step that gathers keyed strings into tables and compiles them per culture; linguistic QA is the pass where fluent testers play a localized build and log errors against the build and the string key ([Production Pipelines & Builds](/books/gaming/production-pipelines#localization)).
- **Locking (exclusive checkout):** checking out a binary asset so nobody else can change it until it's checked back in, because textures and levels can't be merged; built into Perforce, weaker in Git LFS ([Production Pipelines & Builds](/books/gaming/production-pipelines#source-control-for-large-binaries)).
- **Lotcheck, TRC, XRs:** the names of Nintendo's submission check, Sony's requirement list and Microsoft's published Xbox Requirements; the first two are under NDA ([Production Pipelines & Builds](/books/gaming/production-pipelines#platform-certification)).
- **Mainline, release branch:** where development happens, and the branch cut from it for each patch, after which only that patch's fixes (and no new content past the content lock) go in; fixes land in the oldest branch that needs them and merge forward ([Production Pipelines & Builds](/books/gaming/production-pipelines#branching-for-a-live-game)).
- **Middleware:** a licensed library for one engine subsystem (audio such as Wwise or FMOD, physics such as Havok, Jolt or PhysX, video such as Bink, vegetation such as SpeedTree), linked into the engine and usually licensed per title ([The Engine Landscape](/books/gaming/engine-landscape#middleware)).
- **Milestone:** a contracted deliverable (first playable, vertical slice, alpha, beta, gold master) whose acceptance releases a payment; each one is a recorded build ([The Games Business](/books/gaming/games-business#funding-and-deals)).
- **Mini game:** a web-technology game hosted inside another app, such as WeChat, under that app's own platform rules ([The Games Business](/books/gaming/games-business#platforms)).
- **Minidump, symbolication:** a crash capture of each thread's stack, registers and selected memory, turned into functions and line numbers with the exact build's symbols, then grouped by faulting stack; minidumps are personal data ([Production Pipelines & Builds](/books/gaming/production-pipelines#crash-reporting-and-symbolication)).
- **Minimum guarantee, timed exclusive:** an advance against a game's future sales on one store or service, paid in return for selling there only for a contracted window ([The Games Business](/books/gaming/games-business#funding-and-deals)).
- **Performance budget:** a per-platform, per-subsystem limit (frame time, memory, load time, install and patch size) measured on reference hardware, which fails the build when exceeded ([Production Pipelines & Builds](/books/gaming/production-pipelines#performance-budgets)).
- **Platform developer program:** the agreement-gated route to building for a console (ID@Xbox, PlayStation Partners, the Nintendo Developer Portal), whose requirements are under NDA except Microsoft's ([Production Pipelines & Builds](/books/gaming/production-pipelines#porting)).
- **Player profile:** an account inside one game (`player_profiles`), with a name, progression and settings; matches, reports and item instances hang off it ([The Games Business](/books/gaming/games-business#the-core-data-model)).
- **Playtest:** a session where players play a build to show whether they understand and enjoy it; the playtest build is a recorded build with its telemetry tagged ([Production Pipelines & Builds](/books/gaming/production-pipelines#qa-and-playtesting)).
- **Porting, porting house:** taking a game to a platform it wasn't built for (SDK, certification, input, performance, saves, achievements), often contracted to a specialist studio or co-development partner ([Production Pipelines & Builds](/books/gaming/production-pipelines#porting)).
- **Pseudo-localization:** a fake locale made from the source text (accents, padding, CJK characters) run through automated tests so missing strings, overflow and missing glyphs show before translation ([Production Pipelines & Builds](/books/gaming/production-pipelines#localization)).
- **Render interpolation:** drawing a blend of the previous and current simulated states by the accumulator's leftover fraction (alpha), so motion is smooth and always one step behind the newest state; teleports snap instead ([Building Your Own Engine](/books/gaming/building-an-engine#interpolating-render-state)).
- **Royalty statement:** a periodic report of sales by store, region and SKU, the deductions, the split in force and the unrecouped balance, which reconciles to each store's payouts ([The Games Business](/books/gaming/games-business#funding-and-deals)).
- **Royalty (Unreal):** 5% of a product's lifetime gross revenue above $1 million, or 3.5% for a game that launches on the Epic Games Store no later than elsewhere, as of October 2026 ([The Engine Landscape](/books/gaming/engine-landscape#unreal-engine)).
- **Runtime Fee:** Unity's per-install fee, announced in September 2023, narrowed weeks later and cancelled in September 2024 without ever being charged ([The Engine Landscape](/books/gaming/engine-landscape#unity)).
- **Spiral of death:** a simulation that can't keep up with the steps it's asked to take, so each slow frame demands more steps and makes the next one slower; prevented by clamping frame time ([Building Your Own Engine](/books/gaming/building-an-engine#fixed-and-variable-timesteps)).
- **Sub-stepping:** splitting one physics step into smaller steps, which steadies a simulation more than adding solver iterations ([Building Your Own Engine](/books/gaming/building-an-engine#physics)).
- **Sunset:** the end of an online game, when servers shut down or move to a reduced mode and purchases and data must be honored, refunded, exported or deleted; the plan is written before launch ([The Games Business](/books/gaming/games-business#the-life-of-a-game); the law in [When the Servers Shut Down](/books/gaming/consumer-law-and-loot-boxes#when-the-servers-shut-down), the runbook in [End of Service](/books/gaming/live-operations#end-of-service)).
- **Symbols, symbol store:** debug information from the same compile as the executable (PDBs, dSYMs, ELF or Breakpad symbols), matched to it by a build ID, kept in a store and never shipped ([Production Pipelines & Builds](/books/gaming/production-pipelines#crash-reporting-and-symbolication)).
- **Unified clock:** one source of game time that every system reads, recorded for replay; League consolidated 8 clock instances into one and kept a capped variable frame time rather than a fixed step ([Building Your Own Engine](/books/gaming/building-an-engine#league-s-choice-capped-variable-frame-time)).
- **UObject:** Unreal's base class, providing garbage collection, reflection through `UCLASS` and `UPROPERTY` markup, serialization, editor integration and network replication ([The Engine Landscape](/books/gaming/engine-landscape#unreal-engine)).
- **Virtual voice:** a playing sound that isn't mixed; only its position and audibility are tracked until it becomes audible again, so a scene can hold more sounds than the voice limit ([Building Your Own Engine](/books/gaming/building-an-engine#audio)).
- **Work for hire:** a work whose commissioning party is legally its author and copyright owner, so the studio that built it keeps no rights in it ([The Games Business](/books/gaming/games-business#funding-and-deals)).

## Clients and Delivery

- **Activities (PS5):** cards in the PlayStation 5 Control Center that take a player straight into a level or challenge, which a front end can only honor if every mode is reachable by a deep link ([Game Clients & Launchers](/books/gaming/game-clients#console-and-in-engine-front-ends)).
- **Ad mediation:** a client SDK and service that sits between the game and many ad networks and picks the best-paying ad for each slot, such as AppLovin MAX or Unity LevelPlay ([Mobile Games](/books/gaming/mobile-games#ad-mediation-and-rewarded-ads)).
- **AdAttributionKit, SKAdNetwork:** Apple's aggregated, privacy-preserving install attribution, which sends delayed postbacks to the winning ad network instead of exposing a device identifier; AdAttributionKit is the successor ([Mobile Games](/books/gaming/mobile-games#ios-att-and-adattributionkit)).
- **Advertising ID, IDFA:** the resettable device identifiers for advertising on Android and iOS; on iOS the IDFA is all zeros unless the player allows tracking through ATT, and an Android user can delete the Advertising ID ([Mobile Games](/books/gaming/mobile-games#user-acquisition-and-attribution)).
- **ATT (App Tracking Transparency):** Apple's permission prompt an app must show before tracking a user or reading the IDFA; a game may not reward players for accepting it ([Mobile Games](/books/gaming/mobile-games#ios-att-and-adattributionkit)).
- **Background patching:** a launcher downloading and installing patches while it's open, so the game is ready when the player is; the EA app advertises background updates and the Riot Client added them as an opt-in in May 2023 ([Game Clients & Launchers](/books/gaming/game-clients#one-client-for-every-game-the-riot-client)).
- **Binary delta, delta patch:** a new file encoded as copy and insert instructions against one known old version (bsdiff, Courgette, zstd `--patch-from`); smallest for that version, but a release needs a patch per supported old version ([Patching & Content Delivery](/books/gaming/patching#binary-deltas)).
- **Boot set:** the plugins a client loads before it's usable; League's Affinity mechanism for choosing it broke in 2018, so every plugin loaded at bootstrap, which is why the boot set needs an owner and a CI gate ([Game Clients & Launchers](/books/gaming/game-clients#what-the-architecture-cost-and-the-cleanup)).
- **Bundle:** a CDN object grouping many chunks so a download needs few requests; League's data is over 300,000 chunks in fewer than 5,000 bundles, over 85% shared with the previous version ([Patching & Content Delivery](/books/gaming/patching#the-league-patcher-2019)).
- **CEF (Chromium Embedded Framework):** a BSD-licensed project for embedding Chromium in other applications; launchers such as Steam's, Battle.net's and the League client's draw their UI with an embedded Chromium, and Guild Wars 2 uses it inside the game ([Game Clients & Launchers](/books/gaming/game-clients#the-league-client-update)).
- **Channel, staged exposure:** a live or test channel per platform and region that points at one signed release at a time, and moving a release to a share of players or a region at a time while watching failures and crashes ([Patching & Content Delivery](/books/gaming/patching#rollouts-rollbacks-and-hotfixes)).
- **Chunk (content), content-defined chunking:** a variable-size piece of a file, cut where a rolling hash meets a condition and named by its hash, so an insertion shifts only nearby chunks and identical chunks deduplicate; FastCDC is the algorithm League's patcher builds on ([Patching & Content Delivery](/books/gaming/patching#content-defined-chunks)).
- **Conversion value:** the value an iOS app sets for AdAttributionKit postbacks, a 6-bit fine value (0 to 63) in the first postback or a coarse low, medium or high; the schema that maps early player behavior onto it is versioned config ([Mobile Games](/books/gaming/mobile-games#ios-att-and-adattributionkit)).
- **CPI, eCPI:** cost per install, the agreed price per install, and effective CPI, ad spend divided by attributed installs when campaigns are bought on another basis ([Mobile Games](/books/gaming/mobile-games#cpi-roas-and-payback)).
- **Device tier:** a small set of named quality levels, each a bundle of settings, with a versioned rule served from the backend that assigns each device to one ([Mobile Games](/books/gaming/mobile-games#device-fragmentation-and-tiers)).
- **Front-end client:** the out-of-game client a player uses between matches, for sign-in, patching, the store, social features, queues and launching the game process ([Game Clients & Launchers](/books/gaming/game-clients#what-a-client-does)).
- **Game Client API, LCU:** Riot's supported, read-only local HTTPS interface in the running game at `127.0.0.1:2999` (including the Live Client Data API), against the League Client API between CEF and the client's C++ services, which Riot doesn't support for third parties; Counter-Strike's Game State Integration is the push-based counterpart ([Game Clients & Launchers](/books/gaming/game-clients#local-apis-what-riot-supports-and-what-it-doesn-t)).
- **Go-live switch:** flipping the new manifest, the new minimum version and the new server builds at one instant, after preloads have put most bytes on disk, for a game where everyone moves together ([Patching & Content Delivery](/books/gaming/patching#version-compatibility-and-forced-updates)).
- **Host process:** the long-lived client process that owns local services and canonical state (session, social, patching, game launch), so the UI can be closed during a match and rebuilt ([Game Clients & Launchers](/books/gaming/game-clients#process-model)).
- **Install Referrer:** Google Play's API that gives an installed app the referrer URL and click and install timestamps, tying an install to its click without a device identifier ([Mobile Games](/books/gaming/mobile-games#android-advertising-id-referrer-and-the-end-of-privacy-sandbox)).
- **Jetsam, LMK:** the OS killing an app to reclaim memory, called jetsam on iOS and done by the low-memory killer on Android; to the player it looks like a crash, but crash reporters often miss it ([Mobile Games](/books/gaming/mobile-games#memory-thermal-and-battery-budgets)).
- **Launcher:** a program that installs, patches and launches games, with news and a store page, such as Steam, the Epic Games Launcher, Battle.net, the EA app, Ubisoft Connect and the Riot Client ([Game Clients & Launchers](/books/gaming/game-clients#what-a-client-does)).
- **Lookback window:** how long after an ad click or impression an install can still be attributed to it; measurement partners default to 7 days for clicks ([Mobile Games](/books/gaming/mobile-games#measurement-partners)).
- **Loopback API:** a client's local service interface bound to `127.0.0.1` on a port chosen at startup, requiring a per-session secret and rejecting browser origins it doesn't own ([Game Clients & Launchers](/books/gaming/game-clients#local-apis-and-auth)).
- **Manifest:** the list of every file and chunk in a release by content hash, which launchers and patchers read; League's is about 8 MB, signed, and the client loads nothing unsigned ([Patching & Content Delivery](/books/gaming/patching#the-league-patcher-2019); the build's own manifest is in [Production Pipelines & Builds](/books/gaming/production-pipelines#what-a-build-is)).
- **Minimum supported version:** the oldest build allowed to sign in or queue for a game and platform, checked at startup and before queueing with an "update required" screen ([Patching & Content Delivery](/books/gaming/patching#version-compatibility-and-forced-updates)).
- **MMP (mobile measurement partner):** a client SDK and service, such as AppsFlyer or Adjust, that matches installs to ad clicks and impressions, collects forwarded postbacks and reports per campaign; its revenue figures are not the ledger ([Mobile Games](/books/gaming/mobile-games#measurement-partners)).
- **Network protocol version:** a deliberate version carried on every connection and bumped when the wire format changes, not on every build, so servers and matchmaking can decide compatibility ([Patching & Content Delivery](/books/gaming/patching#version-compatibility-and-forced-updates)).
- **Payback day:** the first day N on which a cohort's ROAS reaches 100% ([Mobile Games](/books/gaming/mobile-games#cpi-roas-and-payback)).
- **Plugin (client):** an independently owned and versioned unit of a client, front end (UI in CEF) or back end (C++ services); a League client build is a JSON list of plugins whose semver dependencies must resolve ([Game Clients & Launchers](/books/gaming/game-clients#a-build-is-a-list-of-plugins)).
- **Postback, crowd anonymity tier:** the delayed attribution message a device sends to the ad network after an install, and the tier Apple assigns by how many installs share the campaign, which decides how much detail the postback carries ([Mobile Games](/books/gaming/mobile-games#ios-att-and-adattributionkit)).
- **RADS:** League's binary-delta patcher for eight years; its 2019 chunked replacement downloaded 22% more on patch 9.9 but cut average update time from over 8 minutes to under 40 seconds and failures from 2.2% to 0.3% ([Patching & Content Delivery](/books/gaming/patching#the-league-patcher-2019)).
- **ROAS (day N):** return on ad spend: net revenue from a campaign's attributed install cohort over days 0 to N divided by its ad spend; it always carries its day ([Mobile Games](/books/gaming/mobile-games#cpi-roas-and-payback)).
- **Rollback (release):** pointing a channel at the previous manifest, recorded as a new release with a higher sequence number so clients that refuse older manifests still accept it; not rollback netcode ([Patching & Content Delivery](/books/gaming/patching#rollouts-rollbacks-and-hotfixes)).
- **S2S reward callback:** the server-to-server call an ad network or mediation platform makes when a rewarded ad completes, signed and retried, which the game verifies and grants on once, keyed by the network's event ID ([Mobile Games](/books/gaming/mobile-games#ad-mediation-and-rewarded-ads)).
- **SteamPipe, depot:** Steam's content system, which splits files into roughly 1 MB chunks, patches with binary deltas and publishes each depot build with a 64-bit manifest ID to branches ([Patching & Content Delivery](/books/gaming/patching#steam)).
- **Streaming install, launch set:** Xbox's way of letting a title start once the data it needs to run is installed, with the rest installing in the background ([Patching & Content Delivery](/books/gaming/patching#play-while-downloading)).
- **Thermal state, thermal headroom:** the OS's report of how hot the device is (iOS nominal to critical; Android's thermal status levels) and Android's forecast of how close it is to throttling, which drive a game's step-down ladder ([Mobile Games](/books/gaming/mobile-games#memory-thermal-and-battery-budgets)).
- **Updater attacks (rollback, freeze):** serving an older release to reinstall a vulnerable version, or the same old metadata forever, among the attacks a patcher must resist; defended by signed manifests, monotonic release numbers and short expiry ([Patching & Content Delivery](/books/gaming/patching#integrity-and-signing); the full list is in [Software Updates](/docs/security/software-updates#what-an-updater-must-resist)).

## Multiplayer

- **Agones:** an open-source library for hosting, running and scaling dedicated game servers on Kubernetes, with GameServer and Fleet resources and an SDK the server calls ([Game Servers & Hosting](/books/gaming/game-servers#hosting-options)).
- **Allocation:** handing a forming match a server that is already Ready and returning its address and port; idempotent (keyed by the match ID), atomic and placed by latency ([Game Servers & Hosting](/books/gaming/game-servers#fleets-allocation-and-autoscaling)).
- **Authoritative server:** a server that runs the real simulation; clients send inputs and receive state, and when they disagree the server wins ([Netcode Fundamentals](/books/gaming/netcode#topologies-and-authority)).
- **Backfill:** matching players into a match that already exists, such as one a player left, through a ticket that describes the open slots ([Matchmaking & Ranked](/books/gaming/matchmaking#widening-the-search)).
- **Block:** a one-directional edge that needs no consent and overrides the rest of the social graph: it removes a friendship, hides presence both ways and stops whispers, invites and voice, enforced by every service ([Parties, Presence, Chat & Voice](/books/gaming/social-systems#the-social-graph)).
- **Client-side prediction:** the client running the same movement code as the server on its own inputs and showing the result at once, instead of waiting a round trip ([Netcode Fundamentals](/books/gaming/netcode#client-side-prediction-and-reconciliation)).
- **Connected realms:** realms joined to share one population, the old realms kept as virtual realms running on a host realm's hardware ([Game Servers & Hosting](/books/gaming/game-servers#shards-realms-and-worlds)).
- **Dedicated server, listen server:** a server with no local players, against one where a player's machine hosts the match, has zero latency to the authority and ends the match when it leaves ([Netcode Fundamentals](/books/gaming/netcode#topologies-and-authority)).
- **Desync, first divergence:** machines whose simulations no longer match, found by comparing state checksums per frame or turn; hierarchical state logs are diffed to find the first divergence, because everything after it is noise ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#finding-desyncs)).
- **Deterministic lockstep:** every machine running the whole simulation in turns from identical commands, a turn executing only when every player's commands have arrived, at the speed of the slowest connection ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#deterministic-lockstep)).
- **Drain:** telling a server to finish its match and shut itself down rather than killing it; scale-down and updates never touch an Allocated server ([Game Servers & Hosting](/books/gaming/game-servers#the-server-lifecycle)).
- **Elo, K-factor:** one rating per player, moved after each game by K times the difference between the actual and expected score; FIDE uses K of 40, 20 or 10 by experience and rating ([Matchmaking & Ranked](/books/gaming/matchmaking#elo-by-fide-s-rules)).
- **Entity interpolation:** drawing other players a little in the past, between the two server states that bracket the render time; the interpolation delay is the floor on how old every enemy on screen is, and extrapolation covers only a briefly late packet ([Netcode Fundamentals](/books/gaming/netcode#entity-interpolation)).
- **Fan-out (presence):** telling every online friend allowed to see it when a player's presence changes; its cost is concurrency times change rate times recipients, cut by coalescing changes ([Parties, Presence, Chat & Voice](/books/gaming/social-systems#fan-out)).
- **Fleet, ready buffer:** a set of identical servers (one build, one location) kept warm for allocation, and the number held Ready at all times so matches don't wait for a server to start ([Game Servers & Hosting](/books/gaming/game-servers#fleets-allocation-and-autoscaling)).
- **Frame delay:** a small input delay in a rollback game that reduces the number and length of rollbacks; GGPO's guidance is that more than one frame is noticeable in fighting games ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#rollback)).
- **Friendship:** a mutual, consented edge stored once per pair and hung off the account, so one friends list covers a publisher's games ([Parties, Presence, Chat & Voice](/books/gaming/social-systems#the-social-graph)).
- **Games per core:** the capacity unit of a game server host at a tick rate; VALORANT targeted three 128-tick games per core, 2.34 ms each, with 10% of the frame reserved for the host ([Game Servers & Hosting](/books/gaming/game-servers#the-frame-budget-at-128-ticks)).
- **GGPO:** the MIT-licensed SDK that pioneered rollback networking in peer-to-peer games in 2009, built on save, load and advance callbacks the game implements ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#rollback)).
- **Glicko-2:** a rating with a rating deviation (RD) and a volatility, updated per rating period; the deviation shrinks as evidence arrives and grows while a player is inactive ([Matchmaking & Ranked](/books/gaming/matchmaking#glicko-2-ratings-that-know-their-uncertainty)).
- **Head-of-line blocking:** a lost packet holding up everything behind it until it's retransmitted, as in TCP; the reason real-time games run over UDP and build only the reliability they need ([Netcode Fundamentals](/books/gaming/netcode#reliability-over-udp)).
- **Input recording, keyframe:** a replay stored as the starting state or seed plus every input, tied to the exact build, with periodic state snapshots so playback can seek ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#replays-and-spectating)).
- **Interest management, relevancy:** deciding which entities each client receives and how often; it saves bandwidth and server CPU, and what a client is never sent a wallhack can't show ([Netcode Fundamentals](/books/gaming/netcode#interest-management-and-relevancy)).
- **Iris, Replication Graph:** Unreal's opt-in replication system (Experimental in the 5.8 docs), and the earlier system of persistent nodes and grid cells built because Fortnite's 100 players and about 50,000 replicated actors outgrew per-actor checks ([Netcode Fundamentals](/books/gaming/netcode#interest-management-and-relevancy)).
- **Lag compensation, rewind:** the server reconstructing hitboxes as the shooter saw them, judging the shot there and applying the result in the present, so a target can die after reaching cover on their own screen ([Netcode Fundamentals](/books/gaming/netcode#lag-compensation)).
- **Maintenance window, downtime:** a scheduled period when worlds are offline for changes that need them stopped, as opposed to data hotfixes and rolling restarts ([Game Servers & Hosting](/books/gaming/game-servers#maintenance-windows-and-long-lived-servers)).
- **Match quality score:** a proposed match's predicted closeness plus penalties for ping, party mismatch and role fit, accepted when it clears a threshold that falls as tickets age ([Matchmaking & Ranked](/books/gaming/matchmaking#quality-versus-queue-time)).
- **Matchmaking rating (MMR):** the hidden rating a game uses to make fair matches, kept separate from the visible rank and never shown to the player ([Matchmaking & Ranked](/books/gaming/matchmaking#hidden-mmr-and-visible-rank)).
- **Message classes:** unreliable latest-wins state that is never retransmitted, reliable ordered events on their own channel, and inputs made reliable by repeating every unacknowledged one in each packet ([Netcode Fundamentals](/books/gaming/netcode#reliability-over-udp)).
- **Mock game server:** a lightweight fake that provisions, runs for a match length and reports a result without any gameplay, used to load test the platform at launch scale ([Game Servers & Hosting](/books/gaming/game-servers#load-testing-servers-and-fleets)).
- **Open Match:** Google's open-source matchmaking framework, whose parts (frontend, ticket pool, director, match function, evaluator, assignment) name what every matchmaker has ([Matchmaking & Ranked](/books/gaming/matchmaking#matchmakers-you-can-adopt)).
- **OpenSkill, Weng-Lin:** a Bayesian rating method with closed-form updates for any number of teams, and the open-source libraries that implement it ([Matchmaking & Ranked](/books/gaming/matchmaking#weng-lin-and-openskill)).
- **Party:** players who queue and play together as one ticket, with a leader and the states `open`, `queued`, `in_match` and `disbanded`; any change while queued cancels the ticket ([Parties, Presence, Chat & Voice](/books/gaming/social-systems#parties-and-invites)).
- **Party MMR:** the one number a party matches on, such as an average, a mean weighted toward the highest-rated member, or an average plus a party bonus ([Matchmaking & Ranked](/books/gaming/matchmaking#parties)).
- **Peeker's advantage:** the extra time a player moving around a corner has to react over the player holding the angle, from round trip and buffering; Riot measured about 141 ms in VALORANT and cut it to about 71 ms ([Netcode Fundamentals](/books/gaming/netcode#peeker-s-advantage)).
- **Placement (ranked):** setting a new or returning player's rank from every prior signal, on the low end of where the system thinks they belong, then letting it converge ([Matchmaking & Ranked](/books/gaming/matchmaking#hidden-mmr-and-visible-rank)).
- **Placement (server):** choosing the location that hosts a match from client-measured latency (ping beacons), minimizing the worst player's ping and capping the spread ([Game Servers & Hosting](/books/gaming/game-servers#regions-and-latency-based-placement)).
- **Prediction window:** how far rollback may run ahead on predicted inputs (8 frames in GGPO) before it stalls; one rendered frame must be able to resimulate all of it ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#rollback)).
- **Presence, rich presence:** whether a friend is online, derived from live sessions and held in memory, and the small, typed, localized detail of what they're doing ([Parties, Presence, Chat & Voice](/books/gaming/social-systems#presence)).
- **Queue, ticket:** a pool of waiting requests plus the rules for matching them, and a request from one player or a whole party that can only match within its queue; a ticket moves from `searching` to `proposed` to `assigned`, or ends `cancelled` or `expired` ([Matchmaking & Ranked](/books/gaming/matchmaking#queue-design); states in [The Ticket Model](/books/gaming/matchmaking#the-ticket-model)).
- **Rank, LP, RR:** the visible tier and division a player sees, with points (League Points, VALORANT's Rank Rating) to the next, moving in predictable steps toward MMR ([Matchmaking & Ranked](/books/gaming/matchmaking#hidden-mmr-and-visible-rank)).
- **Reconciliation:** the client taking the server's state as of the last input it processed (by move number), dropping acknowledged inputs, replaying the rest and correcting smoothly if the result differs ([Netcode Fundamentals](/books/gaming/netcode#client-side-prediction-and-reconciliation)).
- **Relay:** a server that forwards packets between players or to game servers without running the game, solving NAT traversal and hiding IP addresses, as Steam Datagram Relay does ([Netcode Fundamentals](/books/gaming/netcode#topologies-and-authority)).
- **Rewind cap:** the limit on how far back the server will rewind for hit registration, set from the latency distribution, with each client's claimed time checked against its measured ping ([Netcode Fundamentals](/books/gaming/netcode#rewind-limits)).
- **Riot Direct:** Riot's own network of routers in major internet hubs, peering directly with ISPs so player traffic avoids lowest-cost routing ([Game Servers & Hosting](/books/gaming/game-servers#the-network-between-player-and-server)).
- **Role queue:** a queue where each team needs one of each role and players list the roles they'll play; the scarce role sets everyone's wait ([Matchmaking & Ranked](/books/gaming/matchmaking#queue-design)).
- **Rollback networking:** applying local input at once, predicting remote input, and when a real input differs, loading the saved state and resimulating to the present within one frame ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#rollback)).
- **Server lifecycle:** the states every orchestrator models: starting, Ready (in the pool), Reserved, Allocated (must not be deleted), Shutdown, and Unhealthy after missed health pings ([Game Servers & Hosting](/books/gaming/game-servers#the-server-lifecycle)).
- **Server meshing:** several servers simulating one shard, each holding authority over some entities and passing it on as they move ([Game Servers & Hosting](/books/gaming/game-servers#zones-seams-and-server-meshing)).
- **Server Network Recording, Delta Checker:** League's complete record of a match's inputs, settings and configuration, replayable on its deterministic server (recording replicated state, as Unreal's replays do, is the alternative that needs no determinism), and the testing tool from recorded inputs that the determinism work began with ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#determinism-on-the-server-league-of-legends)).
- **Single shard:** one persistent world for all players, split across servers by place rather than by copy, as in EVE Online ([Game Servers & Hosting](/books/gaming/game-servers#shards-realms-and-worlds)).
- **Smurf:** an experienced player on a new account, who stomps lower-skill matches while the rating catches up; most alternate accounts are made to play with friends of a different rank ([Matchmaking & Ranked](/books/gaming/matchmaking#new-accounts-and-smurfs)).
- **Snapshot, delta compression:** state sent as everything relevant to a client, or as the differences from the last snapshot the client acknowledged ([Netcode Fundamentals](/books/gaming/netcode#what-crosses-the-wire)).
- **State synchronization:** inputs up and state down, with the server simulating and clients predicting their own character; tolerant of imperfect determinism ([Lockstep, Rollback & Determinism](/books/gaming/determinism-and-rollback#three-ways-to-agree)).
- **Tick rate:** how many times a second the server simulates and sends updates; higher ticks mean fresher state and less buffering for linearly more CPU, so a tick rate is also a hosting budget ([Netcode Fundamentals](/books/gaming/netcode#tick-rate-and-its-costs)).
- **Time Dilation (TiDi):** slowing the game clock on an overloaded server so every player there slows equally instead of the server falling behind ([Game Servers & Hosting](/books/gaming/game-servers#load-time-dilation)).
- **TrueSkill, TrueSkill 2:** Microsoft's Gaussian team rating updated by message passing on a factor graph, and its successor that adds experience, squads, kills and quitting as evidence ([Matchmaking & Ranked](/books/gaming/matchmaking#trueskill-and-trueskill-2-teams)).
- **Voice token, voice channel:** a short-lived credential your server signs for the voice vendor, naming the action, user, channel and expiry, and the channels it opens: positional (3D) per match, non-positional (2D) for teams and parties ([Parties, Presence, Chat & Voice](/books/gaming/social-systems#voice)).
- **WebTransport:** HTTP/3 over QUIC in the browser, with unreliable datagrams for state and reliable streams for the rest ([Netcode Fundamentals](/books/gaming/netcode#transport-libraries)).
- **Widening, expansion:** relaxing a ticket's constraints on a schedule as it ages (FlexMatch calls the steps expansions), skill before latency, with a cap on how far it goes ([Matchmaking & Ranked](/books/gaming/matchmaking#widening-the-search)).
- **World, realm (persistent shard):** one copy of a persistent game world with its own population and database; not the same as a platform shard, which is a regional backend deployment ([Game Servers & Hosting](/books/gaming/game-servers#shards-realms-and-worlds)).
- **Write-behind (character state):** character state held in server memory and flushed to the database on a cadence, so a crash loses the time since the last flush; anything that moves value is written in its own transaction instead ([Game Servers & Hosting](/books/gaming/game-servers#what-is-saved-when)).
- **XMPP:** an XML protocol for messaging and presence with rosters, which Riot's chat is built on and extends ([Parties, Presence, Chat & Voice](/books/gaming/social-systems#protocol-xmpp-or-your-own)).
- **Zoning, seamless handoff:** simulating each region of a world on its own server, with a transfer (a loading screen, or an invisible handoff) when a player crosses between them ([Game Servers & Hosting](/books/gaming/game-servers#zones-seams-and-server-meshing)).

## Backend and Live Services

- **Account deletion requirement:** Apple's and Google's rule that an app that creates accounts lets the player start deletion of the whole account inside the app (and, on Google Play, from the web), not just deactivate it ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#account-deletion-the-stores-require)).
- **Account merge:** folding two accounts into one; the player chooses which profile survives per game, ownership is unioned by revoking and regranting entitlements and moving balances as `merge` ledger transactions (never by editing rows), penalties carry over, and every service applies its step idempotently within a reversal window ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#merging)).
- **Account status:** `active`, `locked` (takeover suspected or recovery in progress) or `closed` (including an account retired by a merge, which names the survivor); a ban is a penalty, never a status ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#how-to-build-it)).
- **Anonymous first, recoverable later:** a device or custom ID login that asks nothing but can't be recovered if the device is lost, and the email or platform login a player is prompted to add at the first purchase or real progress ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#anonymous-first-recoverable-later)).
- **Clawback:** the one algorithm for refunds, voids and chargebacks: find the grant by its store transaction, reverse it, apply a published rule for currency already spent, and record the decision, never locking the account ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#refunds-chargebacks-and-clawbacks)).
- **Cloud save:** a save file copied to a platform's cloud or the game's own storage so it follows the player across devices; platform clouds sync bytes and leave deciding which bytes are right to the game ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#how-the-platforms-do-it)).
- **Config version:** an immutable published snapshot of a game's remote config; a change or a rollback publishes a new version, and clients and telemetry report the version they run ([Live Operations](/books/gaming/live-operations#how-to-build-it)).
- **Cross Save:** Bungie's Destiny 2 model of cross-progression, where the player picks one active account whose characters are reachable everywhere while some purchases stay on their platform ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#cross-progression)).
- **Cross-play, cross-progression, cross-purchase:** players on different platforms in one match, the same profile and rank everywhere, and something bought on one platform usable on another, which store agreements constrain more than technology ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#cross-play-cross-progression-and-cross-purchase)).
- **Data request:** a player's access, export or erasure request, tracked per account with one step for each service that holds their data ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#how-to-build-it)).
- **End of service:** the planned shutdown of a live game's servers, run as a dated plan: notice, a stop on paid sales, refunds, a data export window and an ordered turn-off ([Live Operations](/books/gaming/live-operations#end-of-service)).
- **Entitlement:** a never-deleted record that an account has the right to an item, with its source, a unique `source_ref`, validity and revocation; the source of truth every other view of ownership defers to ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#entitlements-are-the-source-of-truth)).
- **Environment (versioned):** one immutably versioned specification of the client build, server build, service images and config overrides deployed and rolled back together as a set per shard ([Game Backend Architecture](/books/gaming/game-backend#running-it-containers-and-deployment); the release-side record, a release set, is in [Live Operations](/books/gaming/live-operations#how-to-build-it)).
- **Epic Online Services (EOS):** Epic's free cross-platform services, split into Game Services that sign in with any identity provider and Epic Account Services (friends, presence, overlay) that need an Epic account ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#accounts-and-platform-identities)).
- **Event envelope:** the fields every telemetry event carries whatever its type, so any event can be joined to its account, match, build and config ([Telemetry & Analytics](/books/gaming/telemetry#the-event-envelope)).
- **Experiment, variant, exposure:** a test of remote config against a control group, the config overlay each assigned group receives, and the first moment a player actually reached the change, from which results are read ([Game Metrics](/books/gaming/game-metrics#experiments); delivery in [Live Operations](/books/gaming/live-operations#experiments)).
- **Game result (exactly once):** the result a game server reports at match end, ingested once per match from the assigned server only; a second submission is a duplicate or a conflict, never applied twice ([Game Backend Architecture](/books/gaming/game-backend#game-results-exactly-once-per-match)).
- **Global and regional services:** accounts, entitlements, wallets and catalog with one logical home, against parties, matchmaking, match history and game servers that live per shard and fail alone ([Game Backend Architecture](/books/gaming/game-backend#global-and-regional-services)).
- **Heatmap:** a count of events per cell of a map, from server-sampled positions keyed by map version and normalized by time spent in each cell ([Telemetry & Analytics](/books/gaming/telemetry#positions-and-heatmaps)).
- **Hot path, cold path:** the stream that feeds live operations within minutes (concurrency, crash spikes, frame-time alarms) and the scheduled warehouse build of everything else, both from one event stream ([Telemetry & Analytics](/books/gaming/telemetry#the-pipeline)).
- **Hotfix:** a smaller client or server build shipped between patches; a server-only hotfix needs no download ([Live Operations](/books/gaming/live-operations#four-ways-to-change-a-running-game)).
- **Inventory:** what a player can use in one game, the account's live entitlements plus the profile's live item instances, read from a cache and written in transactions that check ownership, quantity and capacity ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#inventories)).
- **Item definition, item instance:** the catalog entry for what an item is (`items`), and one copy held by a player profile with its own state, such as rolled stats or a trade history; items are rights, stackable counts or unique copies ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#definitions-and-instances)).
- **Kill switch:** a flag that disables content or a system without a build (a character, a mode, a store item, a crafting recipe), failing safe for players already using it ([Live Operations](/books/gaming/live-operations#flags-kill-switches-and-remote-config)).
- **Linking, relink cooldown:** attaching a platform identity to an account after proving both sides with fresh credentials, refusing silent moves, and waiting out a cooldown before an unlinked identity can join a different account ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#linking)).
- **Live operations:** the discipline of changing a running game safely and on schedule: patches, hotfixes, server-side data, config, events, experiments and incidents ([Live Operations](/books/gaming/live-operations)).
- **Login queue:** admission control with a user interface at the edge of the account service: a capacity per scope, a ceiling on the queue, honest positions, priority classes and reclaimed idle slots ([Game Backend Architecture](/books/gaming/game-backend#login-queues)).
- **Micropatch, server-side override:** a server-only fix shipped as data the game server loads, replacing the original by key; TFT's fixed a broken burn effect in about an hour, and it must be merged back before the next patch ([Live Operations](/books/gaming/live-operations#four-ways-to-change-a-running-game)).
- **Paid currency, earned currency:** units bought with real money and units granted by play, kept in separate ledger accounts even when the client shows one balance, because refunds, accounting and consumer law treat them differently ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#paid-and-earned-currency-are-different-money)).
- **Patch cadence (train):** a fixed release schedule kept as data that tools read; League's 2026 schedule has 24 patches, mostly two weeks apart, and out-of-band fixes ride faster paths between trains ([Live Operations](/books/gaming/live-operations#cadence)).
- **Platform identity:** an account another company issued (a Steam ID, a PSN account, an Xbox user, an Epic, Apple, Google or Nintendo sign-in), verified server to server and linked to your account by its stable ID, never a name ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#accounts-and-platform-identities)).
- **Platform scope:** where an entitlement may be used: portable across platforms, only on the platform where it was bought, or bounded in time ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#cross-play-cross-progression-and-cross-purchase)).
- **Pseudonymization (erasure):** replacing an erased player's identity with an opaque ID in shared records such as matches and ledgers, so other players' history and the books stay intact ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#erasure-against-append-only-records)).
- **Purchase lot:** one purchase of paid currency tracked as its own balance, so each paid spend is attributed to a lot (first in, first out) and the unspent part of any purchase is a query ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#spend-order)).
- **Release set:** one record per patch, hotfix or override naming the client builds, server build, service versions, config version and content version released together; not Patching's per-build release manifest ([Live Operations](/books/gaming/live-operations#how-to-build-it)).
- **Remote config:** tuning a game without a deploy through versioned key-value parameters, schema-checked, audited, defaulted in the client and applied to game servers at match start ([Live Operations](/books/gaming/live-operations#flags-kill-switches-and-remote-config)).
- **Sample by match:** keeping a deterministic fraction of matches (by hashing the match ID) in full rather than sampling events, so a kept match's paths and per-match questions stay answerable ([Telemetry & Analytics](/books/gaming/telemetry#sampling-at-game-scale)).
- **Save conflict:** two histories of one save produced by devices that played while disconnected; platforms ask the player, hand both versions to the game, or pick by a game metric ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#conflicts-across-devices)).
- **Save format version:** a version in a save's header, separate from the build version, that the loader reads first and migrates forward one step at a time; a build never writes an older format ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#save-formats-and-versioning)).
- **Seasons and events (dated content):** passes, limited-time modes and store rotations shipped dark and activated by a `valid_during` range, with a start rule (one global instant or local midnight) and a minimum client build ([Live Operations](/books/gaming/live-operations#seasons-and-events-are-dated-content)).
- **Server-authoritative progression:** progress held by the backend, with the client showing it and asking to change it; anything paid for, tradeable, shown to others or deciding a match belongs here ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#where-progress-lives)).
- **Server-recorded fact:** a match result, purchase, grant or penalty written by the server or backend; client events are claims, used for behavior and diagnostics only ([Telemetry & Analytics](/books/gaming/telemetry#what-a-game-emits)).
- **Shard, platform:** one regional deployment of the platform with its game servers, the platform being the backend services around the game server (parties, matchmaking, provisioning, results, store) ([Game Backend Architecture](/books/gaming/game-backend#two-halves-game-server-and-platform)).
- **Skin gambling:** third-party sites taking tradable items as stakes, using the platform's sign-in and trading APIs; Valve moved against such sites in 2016 and the UK Gambling Commission prosecuted FUTGalaxy's operators in 2017 ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#trading-and-real-money-markets)).
- **Sources and sinks:** the faucets that create currency and items (rewards, drops, purchases, compensation) and the drains that remove them (store spends, crafting, repair, fees), measured exactly from the ledger ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#sources-and-sinks)).
- **Spend order:** the versioned rule for whether a spend uses paid or earned units first when a player holds both, recorded on each spend because finance, refunds and regulators ask; paid spends are also attributed to purchases first in, first out, so each purchase's unspent remainder is a query ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#spend-order)).
- **Stable ID (PUUID, Riot ID):** the platform's or publisher's permanent player identifier that records key on, against a display name such as a Riot ID (a game name and tag line) that can change ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#accounts-and-platform-identities)).
- **Steam Auto-Cloud:** Steam Cloud's mode that syncs a game's save files on launch and exit without code in the game, showing a conflict window when it can't decide ([Saves, Progression & Player Data](/books/gaming/saves-and-player-data#how-the-platforms-do-it)).
- **Trade hold, escrow:** the wait before a new copy can be traded (Valve recommends at least 72 hours after purchase), and locking items in an open trade so they can't be spent or traded twice ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#trading-and-real-money-markets)).
- **Trade protection, trade reversal:** Counter-Strike 2's July 2025 rule that items received in a trade are protected for a period and trades from the last 7 days can be reversed, which needs each copy's chain of owners ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#trading-and-real-money-markets)).
- **Version skew:** client builds, server builds, services, config and content at different versions at once; managed with exact client-server matches, N and N-1 service support, expand and contract migrations and a minimum client version ([Live Operations](/books/gaming/live-operations#version-skew)).
- **Voided match, abandoned match:** a match undone after the fact (a confirmed cheater, a server fault), marked voided with a reason so consumers reverse their effects, and a match whose server died without reporting, closed by a timeout job ([Game Backend Architecture](/books/gaming/game-backend#game-results-exactly-once-per-match)).
- **Wallet, currency ledger:** an account's balance of one virtual currency, kept as a double-entry ledger whose transactions sum to zero across player, issued and consumed accounts, so the balance is the sum of its entries ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#wallets-are-ledgers)).

## Fair Play and Safety

- **Aimbot, triggerbot:** a cheat that aims or fires for the player using enemy positions and synthetic input; it sends valid inputs, so server authority can't stop it and detection has to ([Anti-Cheat](/books/gaming/anti-cheat#the-threat-model)).
- **Anti-tamper:** a protection layer, such as Denuvo, that makes the game binary and its DRM hard to reverse-engineer or modify; often used for a launch window and removed later ([Anti-Cheat](/books/gaming/anti-cheat#drm-and-license-checks)).
- **Auto-mute:** blocking a zero-tolerance chat message before it's sent and muting the sender, as League's 2023 system does; filtering before delivery fails closed ([Player Behavior & Moderation](/books/gaming/player-behavior#text-chat)).
- **Botting:** software simulating game input, usually unattended, to level accounts for sale or farm currency; Vanguard took League from over a million bot hours a day to under 5,000 ([Anti-Cheat](/books/gaming/anti-cheat#the-threat-model)).
- **Cheat case:** signals per account accumulated into one case with a score and a model version, so automated action happens only at high confidence and the middle band goes to human review ([Anti-Cheat](/books/gaming/anti-cheat#models-and-review)).
- **Children's risk assessment (OSA):** the UK Online Safety Act assessment of risks to children that services likely to be accessed by them had to complete by July 24, 2025 ([Player Behavior & Moderation](/books/gaming/player-behavior#the-online-safety-act)).
- **Client integrity:** client-side protection that makes the game hard to read or modify (encrypted code, randomized anti-debug checks that react late, encrypted values, an obfuscated protocol); it raises cheat costs and decays as cheats adapt ([Anti-Cheat](/books/gaming/anti-cheat#client-integrity)).
- **Content maturity label:** Roblox's labels (Minimal, Mild, Moderate, Content May Vary, Restricted) that decide which age groups can play an experience; unlabeled experiences are restricted for everyone ([Player Behavior & Moderation](/books/gaming/player-behavior#user-generated-content-and-young-players)).
- **Delayed enforcement (ban wave):** collecting signature detections and enforcing later, so cheat sellers learn which check fired as late as possible, while immediate harm in a ranked match is stopped at once ([Anti-Cheat](/books/gaming/anti-cheat#timing)).
- **Disruptive behavior, harmful conduct:** conduct that doesn't match the norms a player and community set, and the subset that causes significant emotional, mental or physical harm, per the Disruption and Harms in Online Gaming Framework ([Player Behavior & Moderation](/books/gaming/player-behavior#what-players-do)).
- **DMA (direct memory access):** reading a game's memory from a second device over PCIe, outside the operating system, which is why kernel anti-cheat can't see everything; not the EU's Digital Markets Act ([Anti-Cheat](/books/gaming/anti-cheat#kernel-anti-cheat)).
- **DRM:** technology that checks a copy of a game was paid for; it protects sales, while anti-cheat protects the fairness of matches ([Anti-Cheat](/books/gaming/anti-cheat#drm-and-license-checks)).
- **DSA Transparency Database:** the European Commission's public database to which online platforms submit their statements of reasons ([Player Behavior & Moderation](/books/gaming/player-behavior#the-digital-services-act)).
- **Easy Anti-Cheat, BattlEye, VAC:** Epic's prevention-first anti-cheat with free and paid tiers, a kernel-based protection system with backend-controlled scanning, and Valve's signature-based system that never bans on reports alone ([Anti-Cheat](/books/gaming/anti-cheat#kernel-anti-cheat)).
- **Hardware ban:** a ban on a hard-to-change device identifier, such as the TPM, so a banned player can't just make a new account; stored hashed, with an end date and an appeal path for secondhand and shared machines ([Anti-Cheat](/books/gaming/anti-cheat#enforcement-bans-hardware-bans-and-appeals)).
- **In-game support SDK:** a help center and ticket or messaging inside the game, filled with context the game already knows; on consoles it can hand off to a phone by QR code ([Player Support](/books/gaming/player-support#channels)).
- **In-match report:** a report filed when the behavior happens, naming the match, channel and category, with the server attaching evidence from its own records and weighing the reporter's credibility ([Player Behavior & Moderation](/books/gaming/player-behavior#reporting-in-the-match)).
- **Intentional feeding, AFK:** losing on purpose by walking into the enemy, and going idle or leaving; detected from match telemetry by the game team, with frequency-based penalties for leaving ([Player Behavior & Moderation](/books/gaming/player-behavior#gameplay-disruption)).
- **Kernel anti-cheat:** an anti-cheat driver running with the operating system's privilege, often loaded at boot, so user-mode cheats can't outrank it; it risks stability and abuse, and Proton doesn't support it on Linux and Steam Deck ([Anti-Cheat](/books/gaming/anti-cheat#kernel-anti-cheat); its risks are in [The Risks of Kernel Drivers](/books/gaming/anti-cheat#the-risks-of-kernel-drivers)).
- **Notice and action:** the DSA Article 16 mechanism that lets anyone flag illegal content to a hosting service, which must process the notice and tell the notifier the outcome; it covers game chat and UGC as well as IP claims ([Player Behavior & Moderation](/books/gaming/player-behavior#the-digital-services-act); [UGC & Creator Economies](/books/gaming/creator-economies#ip-and-takedowns)).
- **Online platform (DSA):** a hosting service that disseminates user content to the public, which brings duties beyond notice and action such as internal complaint handling and submissions to the Transparency Database ([Player Behavior & Moderation](/books/gaming/player-behavior#the-digital-services-act)).
- **Operation (support):** a named, idempotent action support takes on an account (grant, restore, reverse a takeover), capped by value and approved by a second person above a threshold; there is no operation for changing sign-in details or ending a ban ([Player Support](/books/gaming/player-support#how-to-build-it)).
- **Ownership verification:** a server-side check through the store's API that an account owns the game or DLC, the server-trusted form of a license check ([Anti-Cheat](/books/gaming/anti-cheat#drm-and-license-checks)).
- **Penalty ladder:** escalating responses per behavior that restrict the abused feature first (chat, queue, ranked) before the account, with zero-tolerance violations skipping straight to a permanent ban ([Player Behavior & Moderation](/books/gaming/player-behavior#penalties-and-reform)).
- **Prevalence, time to action:** the share of matches with a cheater by mode and region, and the matches from first detection to enforcement; Riot reported League dropping from 45+ games to under 10 after Vanguard ([Anti-Cheat](/books/gaming/anti-cheat#timing)).
- **Prevention, detection, deterrence:** the three parts publishers organize anti-cheat into (Riot names them; Valve's Steamworks guidance covers the same ground), with prevention preferred because it stops cheating before players meet the cheater ([Anti-Cheat](/books/gaming/anti-cheat#the-threat-model)).
- **Proactive detection:** scanning content before anyone reports it; Xbox scanned 14.8 billion items in 2025 and found far more violations than players reported ([Player Behavior & Moderation](/books/gaming/player-behavior#automation-at-scale)).
- **Reform:** the goal of most penalties, since most disruptive players are only sometimes disruptive; consequences work when they're specific, prompt and proportionate, with strikes that expire ([Player Behavior & Moderation](/books/gaming/player-behavior#penalties-and-reform)).
- **Request a Human:** a button that hands a bot-answered support ticket to a person, which brought Riot's bot satisfaction up to match agents; denials stay with people ([Player Support](/books/gaming/player-support#classify-route-answer)).
- **Scripting:** third-party programs that attach to the game client to read its state and automate precise actions; as many as 1 in 15 League games had a scripter or botter before Vanguard ([Anti-Cheat](/books/gaming/anti-cheat#the-threat-model)).
- **Secure Boot and TPM requirements:** PC shooters requiring the platform's verified boot chain (Battlefield 6) or TPM 2.0 and Secure Boot (Call of Duty: Black Ops 7) so a cheat driver can't load before the anti-cheat ([Anti-Cheat](/books/gaming/anti-cheat#kernel-anti-cheat)).
- **Shadow mode:** running a moderation vendor against a labeled sample of your own reports, without acting, before it's allowed to decide anything ([Player Behavior & Moderation](/books/gaming/player-behavior#automation-at-scale)).
- **Statement of reasons:** the explanation DSA Article 17 requires a hosting service to give a user it restricts: the restriction, the facts, whether automation was used, the ground and the redress ([Player Behavior & Moderation](/books/gaming/player-behavior#the-digital-services-act)).
- **Trust and safety:** the policy, intake, decisions, penalties, appeals, audit and reporting a product runs against abuse; the general system is the playbook's, and games add matches, real-time channels and gameplay detection ([Player Behavior & Moderation](/books/gaming/player-behavior); [Trust & Safety](/docs/security/trust-and-safety)).
- **Vanguard:** Riot's anti-cheat, a user-mode client plus a kernel driver loaded at boot that sends nothing back, using TPM 2.0 as a hard-to-fake hardware identifier ([Anti-Cheat](/books/gaming/anti-cheat#kernel-anti-cheat)).
- **Voice evaluation:** moderating voice by recording on a short fuse and evaluating on report (VALORANT keeps recordings 24 hours, 7 days if reported) or by analyzing live channels and surfacing events with clips (ToxMod) ([Player Behavior & Moderation](/books/gaming/player-behavior#voice)).
- **Wallhack, ESP, map hack:** cheats that show enemies, items or state the player shouldn't see, read from client memory; defeated by withholding hidden state ([Anti-Cheat](/books/gaming/anti-cheat#the-threat-model)).
- **Withholding hidden state (Fog of War):** the server not sending enemy positions until a client needs to display them, the general form being per-client relevancy as in Unreal; VALORANT does it with a precomputed potentially visible set at under 2% of server frame time ([Anti-Cheat](/books/gaming/anti-cheat#withholding-hidden-state)).
- **Zero tolerance:** the categories (threats, sexual content involving minors, extremism) that skip the penalty ladder and, in chat, are auto-muted before they're sent ([Player Behavior & Moderation](/books/gaming/player-behavior#text-chat); the ladder in [Penalties and Reform](/books/gaming/player-behavior#penalties-and-reform)).

## Money

- **Active Spender:** Roblox's qualifying user for Creator Rewards, one who has spent at least $9.99 in the past 60 days ([UGC & Creator Economies](/books/gaming/creator-economies#how-creators-get-paid)).
- **appAccountToken, purchase token:** the UUID set at purchase that Apple returns in the transaction to tie it to your account, and Google's globally unique key for a purchase, which must be acknowledged within three days or it's refunded ([Stores, Fees & Payments](/books/gaming/stores-and-payments#receipt-validation-and-entitlement-grants)).
- **Battle pass:** a time-limited reward track with a free lane and a premium lane bought for the season; progress is the sum of awards keyed by the server event that earned them, rewards are entitlements granted on reaching a tier, and upgrading mid-season grants every earlier premium tier at once ([Monetization Models](/books/gaming/monetization#battle-passes)).
- **Cash-out, DevEx:** converting a creator's earned currency into money; Roblox's Developer Exchange converts earned Robux (never purchased Robux) above a minimum balance ([UGC & Creator Economies](/books/gaming/creator-economies#cash-out)).
- **Chargeback:** a payment reversed by the cardholder's bank, possibly months later; virtual goods invite friendly fraud, and a chargeback revokes what it paid for without locking the account ([Stores, Fees & Payments](/books/gaming/stores-and-payments#refunds-and-chargebacks)).
- **Content version (UGC):** one immutable, reviewed version of a creator's island, experience, mod or item; players get the approved version until a new one passes review ([UGC & Creator Economies](/books/gaming/creator-economies#content-pipelines-and-review)).
- **Core Technology Commission:** Apple's 5% commission in the EU on digital sales in apps distributed outside the App Store ([Stores, Fees & Payments](/books/gaming/stores-and-payments#european-union)).
- **Creator:** a user who uploads content that runs inside the game and may earn money from it, a payee with identity, tax and age rules of its own ([UGC & Creator Economies](/books/gaming/creator-economies)).
- **Creator code, Support-A-Creator:** a code a player enters so a share of their purchases goes to a creator for a period; an effective-dated attribution whose accruals reverse on refund ([UGC & Creator Economies](/books/gaming/creator-economies#affiliate-codes-and-drops)).
- **Curated Workshop:** a Steam Workshop where the developer approves each item, the usual form for paid user content ([UGC & Creator Economies](/books/gaming/creator-economies#content-pipelines-and-review)).
- **Dark pattern:** a purchase-flow design that tricks players into charges; the FTC's 2023 order bars Epic from charging through dark patterns or without express consent ([The FTC's Orders](/books/gaming/consumer-law-and-loot-boxes#the-ftc-s-orders)).
- **Deferred revenue:** virtual currency bookings recorded as owed and recognized over time; Roblox recognizes durable items over the estimated life of a paying user, 27 months as of December 31, 2025 ([Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#accounting-for-virtual-currency)).
- **DLC, expansion, season pass:** added content that depends on the base game, and a pre-purchase of DLC not yet made, granted by a job that walks pass holders as each piece ships ([Monetization Models](/books/gaming/monetization#dlc-expansions-and-season-passes)).
- **DMA (Digital Markets Act):** the EU law under which the app stores changed what apps in the EU may link to and charge outside store billing; not direct memory access ([Stores, Fees & Payments](/books/gaming/stores-and-payments#european-union)).
- **DMCA safe harbor, counter-notice, repeat infringer:** the US host protection under 17 U.S.C. § 512, in exchange for a designated agent, expeditious takedown on a valid notice, restoration 10 to 14 business days after a counter-notice unless the claimant sues, and a policy terminating repeat infringers ([UGC & Creator Economies](/books/gaming/creator-economies#ip-and-takedowns)).
- **Drops:** in-game items a viewer earns by watching a stream, claimed on the streaming platform and granted by the game once the accounts are linked ([UGC & Creator Economies](/books/gaming/creator-economies#affiliate-codes-and-drops)).
- **Durable, consumable:** an item owned for good (a skin, a character), and one used up (a boost, a currency pack), refundable only until consumed ([Monetization Models](/books/gaming/monetization#free-to-play-items-and-currency)).
- **Earned Robux:** Robux a creator earned from other players, the only Robux Developer Exchange will convert, and so a liability the platform owes ([UGC & Creator Economies](/books/gaming/creator-economies#cash-out)).
- **Edition:** a bundle of entitlements (base license, a cosmetic pack, early access), each sellable alone, never a flag on the account ([Monetization Models](/books/gaming/monetization#premium-and-paid-upfront)).
- **Engagement pool:** a share of platform revenue divided among creators by how much paying players engage with their content, as in Fortnite's Engagement Pool ([UGC & Creator Economies](/books/gaming/creator-economies#how-creators-get-paid)).
- **Fee schedule:** store rates kept as data per store, program, region and transaction kind, with validity ranges and sources, because court orders and programs keep changing them ([Stores, Fees & Payments](/books/gaming/stores-and-payments#receipt-validation-and-entitlement-grants)).
- **Free-to-play:** no price to start, with revenue from a minority who buy items, currency and passes; where the ownership and economy systems become mandatory ([Monetization Models](/books/gaming/monetization#free-to-play-items-and-currency)).
- **Gross bookings, net to developer:** the sum of purchase prices before tax, and what remains after the store's fee ([Monetization Models](/books/gaming/monetization#the-funnel-in-numbers)).
- **In-App Purchase (IAP):** Apple's billing for in-app digital goods, required for in-game currencies; 30% standard, 15% in the Small Business Program, and 26% in the EU from 1 October 2026 ([Stores, Fees & Payments](/books/gaming/stores-and-payments#apple-app-store)).
- **Link-out (steering):** sending a player from the app to buy on the web; allowed in the US App Store since 1 May 2025 with its commission still in court, and in the EU at 15% on sales within 7 days of the link tap ([Stores, Fees & Payments](/books/gaming/stores-and-payments#apple-app-store)).
- **Luau sandbox:** Roblox's scripting language and VM, with file, debug and bytecode loading removed and each script isolated, the model for treating creators' code as hostile ([UGC & Creator Economies](/books/gaming/creator-economies#sandboxing-user-scripts)).
- **Net Receipts:** Microsoft's fee base: customer payments minus taxes collected, refunds and chargebacks, and amounts owed to Microsoft; 12% for PC games and 30% for Xbox console games ([Stores, Fees & Payments](/books/gaming/stores-and-payments#microsoft-store-and-xbox)).
- **Offer, offer price:** a sellable bundle of items with its rules and audience, priced by dated rows per store and market, one live price each, so a price change is a new row with a reason ([Monetization Models](/books/gaming/monetization#personalized-shops)).
- **Personalized shop:** a shop that shows each player different items chosen by a recommender (Riot's Your Shop, one public example, uses collaborative filtering), with eligibility filters after scoring and the same price for the same item ([Monetization Models](/books/gaming/monetization#personalized-shops)).
- **Premium:** paying once up front for a license the player owns for as long as the account exists, plus optional DLC ([Monetization Models](/books/gaming/monetization#premium-and-paid-upfront)).
- **Receipt validation:** verifying a purchase with the store's server before granting anything; the store transaction moves from `pending` to `verified`, `granted` and `acknowledged`, or to `rejected` or `reversed` ([Stores, Fees & Payments](/books/gaming/stores-and-payments#receipt-validation-and-entitlement-grants)).
- **Regional pricing:** prices per store, currency or region with validity ranges, conversion method and cooldowns; Steam offers exchange-rate, purchasing-power and multi-variable conversion ([Stores, Fees & Payments](/books/gaming/stores-and-payments#regional-pricing)).
- **Rewarded ad:** an ad the player chooses to watch for an in-game reward, granted only on the ad network's server-side verification callback, never on the client's word ([Monetization Models](/books/gaming/monetization#ads-in-mobile-games); [Mobile Games](/books/gaming/mobile-games#ad-mediation-and-rewarded-ads)).
- **Seller (merchant of record):** the party that takes the payment and owns refunds, chargebacks and usually tax; the store on a closed platform, you on your own web store ([Stores, Fees & Payments](/books/gaming/stores-and-payments#who-is-the-seller)).
- **Steam microtransaction:** Steam's purchase flow through the Steam Wallet, `InitTxn` with your order ID, player authorization, `FinalizeTxn` to grant, and `GetReport` at least daily to reconcile refunds and chargebacks ([Stores, Fees & Payments](/books/gaming/stores-and-payments#steam)).
- **Store fee:** the store's share of a sale, from 12% (Epic after the first $1 million, Microsoft PC games) to 30% (Steam under $10 million, Xbox console, Apple IAP), as of October 2026 ([Stores, Fees & Payments](/books/gaming/stores-and-payments#who-is-the-seller)).
- **Store transaction:** one purchase at any store as a row with a state machine (`pending`, `verified`, `granted`, `acknowledged`, or `rejected` and `reversed`), keyed by the store's transaction ID so it grants once ([Stores, Fees & Payments](/books/gaming/stores-and-payments#receipt-validation-and-entitlement-grants)).
- **Subscription:** a monthly fee for a library or online play from the platform, or a benefit for a period inside one game; either way an entitlement with a validity range, not a flag ([Monetization Models](/books/gaming/monetization#subscriptions)).
- **UEFN, Fortnite Developer Program:** Unreal Editor for Fortnite, the tool for building Fortnite islands, and Epic's program through which island creators are paid ([UGC & Creator Economies](/books/gaming/creator-economies#how-the-platforms-do-it)).
- **UGC (user-generated content):** content players build that runs inside a game: experiences, islands, mods, maps and items ([UGC & Creator Economies](/books/gaming/creator-economies)).
- **Virtual currency:** a balance bought in packs and spent on items, smoothing regional prices and enabling small purchases while hiding the real price, which is where regulators step in ([Monetization Models](/books/gaming/monetization#virtual-currency)).
- **Web store:** selling directly outside platform billing for margin and the customer relationship, while taking on tax, fraud, chargebacks, identity and link-attribution tokens ([Stores, Fees & Payments](/books/gaming/stores-and-payments#web-stores-and-direct-payments)).

## The Rules

- **AB 2426:** the California law, in force from 2025, that bars "buy" or "purchase" wording for revocable digital goods unless the buyer is told, or acknowledges, that the purchase is a license ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#california-s-license-disclosure-law)).
- **Accessibility Nutrition Labels:** Apple's per-device App Store declarations of supported accessibility features, voluntary to start ([Accessibility](/books/gaming/accessibility#store-accessibility-tags)).
- **Accessibility settings:** settings per account with device overrides, seeded from the platform's caption, contrast and narration settings, reachable before the first cinematic, and never reset by live config ([Accessibility](/books/gaming/accessibility#settings-as-a-system)).
- **Accessible Games Initiative:** the ESA-led set of voluntary accessibility tags with criteria, announced March 20, 2025 ([Accessibility](/books/gaming/accessibility#store-accessibility-tags)).
- **Action remapping:** binding physical inputs to actions through a table the player edits, with hold, toggle and repeat as properties of the binding and every prompt reading the current binding ([Accessibility](/books/gaming/accessibility#input-and-remapping)).
- **Age band:** an account's age as a band (`under_13`, `13_15`, `16_17`, `adult`, `unknown`) rather than a birth date, derived from its age signals (the lowest wins) and cached on the account, never set directly; unknown gets the youngest band's defaults ([Accounts, Identity & Cross-Platform](/books/gaming/accounts-and-identity#age-and-parental-controls); the rules it drives are in [Ratings, Age & Children](/books/gaming/ratings-and-age#age-and-features)).
- **Age signals:** platform APIs that pass a player's age band to the game under state app-store laws: Apple's Declared Age Range API and Google's Play Age Signals API; each answer is stored as an append-only signal the account's band is derived from ([Ratings, Age & Children](/books/gaming/ratings-and-age#platform-age-signals)).
- **Assists:** separate settings (game speed, timing windows, skipping events, aim help) rather than difficulty presets, with a per-mode policy and the assist state recorded on the match participant ([Accessibility](/books/gaming/accessibility#difficulty-and-assists)).
- **Build features join:** a CI join of `build_features`, the features a build declares (paid random items, time-limited offers, chat) and what the live ratings say, so a new feature triggers a re-rating before release ([Ratings, Age & Children](/books/gaming/ratings-and-age#ratings-as-data)).
- **Camera comfort:** settings that scale or disable camera shake, bob, sway, motion blur and automatic camera movement, plus an adjustable field of view ([Accessibility](/books/gaming/accessibility#motion-and-camera-comfort)).
- **Consolidated rate:** the effective chance of a top-tier item once pity is counted; a 1% base rate with a guarantee on the 50th draw gives 39.50 expected draws, a 2.53% rate ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#pity-and-the-effective-rate)).
- **Controller Assist, Copilot:** platform features that merge two controllers into one input below the game, so a helper can play alongside the player ([Accessibility](/books/gaming/accessibility#adaptive-controllers-and-system-remapping)).
- **COPPA:** the US rule for online services directed to children under 13 or with actual knowledge of one; in games it reaches display names usable as contact information, voice audio and persistent identifiers ([Ratings, Age & Children](/books/gaming/ratings-and-age#coppa-in-games)).
- **CPC principles:** the EU consumer authorities' March 2025 principles on purchased virtual currency: real-money prices, no obscured costs or forced bundles, pre-contractual information, withdrawal rights, fair terms and care for minors ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#the-eu-s-principles-on-in-game-virtual-currencies)).
- **CVAA:** the US law requiring advanced communications services, a category in-game text and voice chat can fall into, to be accessible where achievable; the FCC's class waiver for video game software ended on December 31, 2018 ([Accessibility](/books/gaming/accessibility#the-law)).
- **Drop table:** the possible outcomes of a random draw and their weights, versioned with integer weights, immutable once published, and the single source for both the server's roll and the disclosed odds ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#odds-as-data); each roll is an `item_rolls` row in [Inventories, Entitlements & Economies](/books/gaming/economies-and-entitlements#crafting-and-loot)).
- **DSA (Digital Services Act):** the EU law whose Article 28 bars ads based on profiling on online platforms when the provider is reasonably certain the user is a minor, and whose Articles 16, 17 and 20 set notice-and-action, statement-of-reasons and complaint duties for game chat and UGC ([Player Behavior & Moderation](/books/gaming/player-behavior#regulatory-duties); [Monetization Models](/books/gaming/monetization#ads-in-mobile-games)).
- **Effects intensity:** a player setting that dims or removes flashes, strobes and patterns, deliberately not called an epilepsy safe mode ([Accessibility](/books/gaming/accessibility#photosensitivity)).
- **End-of-life patch, offline mode:** a final update that lets a game run without the publisher's backend, usually saving progress locally and disabling online systems ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#offline-modes-and-end-of-life-patches)).
- **ESRB:** the North American rating board (E, E10+, T, M, AO), whose Interactive Elements such as In-Game Purchases (Includes Random Items) label a game without changing its age rating ([Ratings, Age & Children](/books/gaming/ratings-and-age#esrb)).
- **Geofence:** turning a feature off by region, keyed to the billing country and store region rather than the IP address alone, as paid random items are for Belgium ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#gates-around-the-draw)).
- **IARC:** the International Age Rating Coalition's system, where one questionnaire issues each participating authority's rating for digital storefronts; the answers are stored with the build they described ([Ratings, Age & Children](/books/gaming/ratings-and-age#iarc)).
- **Integer weights:** odds stored as whole-number weights over a fixed total (10,000 makes each unit 0.01%), so displayed probabilities are exact and sum to 100.00 ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#odds-as-data)).
- **Kompu gacha (complete gacha):** a prize for collecting a full set of items from paid draws, held unlawful in Japan in 2012 under the premiums law ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#south-korea-and-japan)).
- **Loot box, paid random item:** a purchase whose contents the buyer doesn't know in advance (gacha, card packs, prize wheels), including ones bought with currency bought for money ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes)).
- **Odds audit:** a daily test of observed outcomes against the disclosed base and consolidated rates per live table version, with the results kept as the answer to anyone who asks ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#auditing-the-odds)).
- **Odds disclosure:** publishing the chance of each item before purchase, required by Apple, Google Play and China, and in the FTC's HoYoverse order together with multi-tiered currency exchange rates ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#store-odds-rules)).
- **Online Safety Act:** the UK law reaching any service where users interact with each other, which puts game chat and voice in scope; Ofcom enforces its illegal-harms and children's duties ([Ratings, Age & Children](/books/gaming/ratings-and-age#coppa-in-games); [Player Behavior & Moderation](/books/gaming/player-behavior#the-online-safety-act)).
- **PEGI:** the European rating system (3, 7, 12, 16, 18) whose interactive risk descriptors now change the age: paid random items are PEGI 16 by default for games submitted from June 2026, and existing games were re-rated from October 2026 ([Ratings, Age & Children](/books/gaming/ratings-and-age#pegi)).
- **Photosensitivity (flash thresholds):** flashing or patterns that can trigger seizures; content fails at more than about three luminance or saturated-red flashes a second over a large part of the screen, so the renderer budgets flashes and every build is tested ([Accessibility](/books/gaming/accessibility#photosensitivity)).
- **Pity:** a guarantee of a top-tier result after a number of draws without one (soft pity raises the rate before it); counters are derived from openings and stored on each one ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#pity-and-the-effective-rate)).
- **Play-by-appointment:** rewards for returning, such as daily quests and login streaks; PEGI 7 from June 2026, and PEGI 12 when players lose content or progress for not returning ([Ratings, Age & Children](/books/gaming/ratings-and-age#pegi)).
- **Private server edition:** a release of a game's server software that players can host themselves after the official servers close ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#offline-modes-and-end-of-life-patches)).
- **Real-name registration:** China's requirement that every game account is registered and signed in with a verified identity, which the minors' playtime limits depend on ([Ratings, Age & Children](/books/gaming/ratings-and-age#other-regions-and-store-ratings)).
- **Right of withdrawal:** the EU's 14-day cancellation right; lost for digital content only with express consent, and treated by the CPC principles as still covering unused purchased currency ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#refund-rights)).
- **Screen narration:** UI read by the platform screen reader or a speech synthesizer in the order name, role, value, position, which needs an accessibility tree under the UI ([Accessibility](/books/gaming/accessibility#screen-narration)).
- **Self-classification (Korea):** age rating by GRAC-designated operators such as storefronts, which GRAC monitors and can override ([Ratings, Age & Children](/books/gaming/ratings-and-age#other-regions-and-store-ratings)).
- **Significant change:** under Utah's app-store law, a material change such as new monetization features or an altered age rating, which needs a parent's approval before a child sees it ([Ratings, Age & Children](/books/gaming/ratings-and-age#platform-age-signals)).
- **Speech-to-text, text-to-speech chat:** other players' voice shown as live text, and typed text spoken on the voice channel; blocks, mutes and filters apply to both ([Accessibility](/books/gaming/accessibility#speech-to-text-and-text-to-speech-chat)).
- **Spending limit:** a per-account cap on real-money purchases per day, week or month, set by default, the player, a parent or support, and checked against pending and completed purchases before one starts; child accounts start at zero ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#gates-around-the-draw)).
- **Stop Killing Games, Stop Destroying Videogames:** the campaign and its European Citizens' Initiative asking that games sold in the EU be left playable after support ends; the Commission declined to legislate in June 2026 ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#the-citizens-initiative-and-the-uk-petition)).
- **Subtitles, captions:** text for speech, and text for all audio including sound effects and who is speaking; at most 40 characters a line and two lines on screen, on before the first sound ([Accessibility](/books/gaming/accessibility#subtitles-and-captions)).
- **Support for the internal operations:** COPPA's exception allowing persistent identifiers without consent for keeping a service working, security and anti-cheat, never for profiling or behavioral ads ([Ratings, Age & Children](/books/gaming/ratings-and-age#coppa-in-games)).
- **Usage risks (USK):** interactive features such as chat, purchases, random items and location sharing that Germany's USK has weighed in age ratings since 2023 ([Ratings, Age & Children](/books/gaming/ratings-and-age#other-regions-and-store-ratings)).
- **VR comfort rating:** a store's required label for how much camera and player motion a VR app has; Meta's are Comfortable, Moderate and Intense ([Accessibility](/books/gaming/accessibility#vr-comfort)).
- **Whale:** a player who spends far more than most; the EU's CPC principles say games whose business model targets them are assessed against a stricter threshold ([Loot Boxes & Consumer Law](/books/gaming/consumer-law-and-loot-boxes#the-eu-s-principles-on-in-game-virtual-currencies)).
- **Xbox Accessibility Guidelines (XAGs):** Microsoft's numbered best practices for game accessibility (101 text, 102 contrast, 104 subtitles, 106 narration, 107 input, 117 motion, 118 photosensitivity, 119 speech-to-text and text-to-speech), with testable numbers but no compliance role ([Accessibility](/books/gaming/accessibility#the-guidelines)).

## Running the Platform

- **Active (player):** an account that sent at least one event from a named list of gameplay events on a day, so background pings and failed logins don't count ([Game Metrics](/books/gaming/game-metrics#engagement-dau-mau-and-stickiness)).
- **ARPDAU, ARPU, ARPPU:** net revenue per daily active player, per monthly active player in a calendar month, and per paying player in a period; computed on gross bookings instead, the name says so ("ARPU on gross bookings"); vendors differ, with GameAnalytics counting in-app purchases only and Unity including ad revenue ([Game Metrics](/books/gaming/game-metrics#revenue-arpdau-arppu-conversion-and-ltv)).
- **Behavior tree:** NPC decisions as a hierarchy of selectors and sequences over tasks, with a Blackboard holding its data and decorators that observe conditions and abort branches ([AI in Games](/books/gaming/ai-in-games#deciding-state-machines-behavior-trees-and-statetree)).
- **Bot standing in for a player:** a match slot filled by a bot: a `match_participants` row with a `bot_key` and no profile, so ratings, reports and metrics leave it out ([AI in Games](/books/gaming/ai-in-games#how-to-build-it)).
- **Cabined account:** Epic's restricted account for younger players, which needs a parent or guardian to complete setup before features such as AI conversations are available ([AI in Games](/books/gaming/ai-in-games#what-ships-today)).
- **Calibration:** whether matches predicted at, say, 60/40 are won by the favorite about 60% of the time, checked against the prediction stored on the match when it was made ([Game Metrics](/books/gaming/game-metrics#match-quality)).
- **Competitive ruling:** a sanction on a person, roster or organization under a tournament's rules, provisional until final, linked to a penalty only when an account is also restricted ([Esports & Spectating](/books/gaming/esports-and-spectating#integrity)).
- **Concurrent users (CCU), peak CCU:** players connected at one instant, and the highest count in a period, from fixed-interval samples with "connected" defined per tier ([Game Metrics](/books/gaming/game-metrics#sessions-and-concurrency)).
- **Considerations, EQS:** utility AI's per-factor scores normalized between 0 and 1, and Unreal's Environment Query System, which applies the same scoring to candidate places and targets ([AI in Games](/books/gaming/ai-in-games#scoring-utility-ai)).
- **Conversion (payer conversion):** the share of active players who made a purchase in a named window, daily (over DAU) or monthly (over MAU); GameAnalytics reports it per day, and a monthly figure is a different number ([Game Metrics](/books/gaming/game-metrics#revenue-arpdau-arppu-conversion-and-ltv)).
- **Crash rate:** crashes per 1,000 sessions, and the share of daily actives who crashed; Google Play's bad behavior threshold is 1.09% of daily actives ([Game Metrics](/books/gaming/game-metrics#technical-health)).
- **DAU, MAU, stickiness:** distinct active accounts on a day, across the 30 days ending on a day (rolling) or a calendar month, and their ratio ([Game Metrics](/books/gaming/game-metrics#engagement-dau-mau-and-stickiness)).
- **Digital replica consent:** a performer's scoped, separate consent to a voice or likeness replica (which game, which characters, real-time or pre-generated), checked before generation, with every generated line counted ([AI in Games](/books/gaming/ai-in-games#performers-and-digital-replicas)).
- **Game AI, generative AI:** deterministic NPC decision and movement code a designer tunes, against model-produced text, speech and art with their own latency, cost and safety problems; generative output is at most a request to the game AI layer ([AI in Games](/books/gaming/ai-in-games#two-kinds-of-ai-two-sets-of-rules)).
- **Ghosting:** relaying a live spectator feed, which shows both teams, to a player; prevented by a server-side delay past the time the information would help ([Esports & Spectating](/books/gaming/esports-and-spectating#spectating-who-sees-what-when)).
- **LTV (realized, predicted):** net revenue per cohort member to day N, which can be audited, and a forecast to a horizon labeled with its model version ([Game Metrics](/books/gaming/game-metrics#revenue-arpdau-arppu-conversion-and-ltv)).
- **Match intervention:** a pause, resume, restore, remake or side swap in a competitive match, recorded as a ruling with the official and the reason ([Esports & Spectating](/books/gaming/esports-and-spectating#replays-rewinds-and-recovery)).
- **Match-fixing, integrity program:** competitors not trying to win, often for betting, and the code of conduct, bet monitoring, investigations and published rulings a publisher runs against it ([Esports & Spectating](/books/gaming/esports-and-spectating#integrity)).
- **Navigation mesh:** a simplified polygon map of where agents can walk, divided into tiles that rebuild locally, with area costs and a separate local avoidance step for crowds ([AI in Games](/books/gaming/ai-in-games#moving-navigation)).
- **Observer:** production staff driving the broadcast cameras from a spectator client connected live to the game server; Riot said in 2022 that its esports matches run with up to 20 observers, while the CS Major configuration caps a server's spectators at 10 ([Esports & Spectating](/books/gaming/esports-and-spectating#spectating-who-sees-what-when)).
- **Official data feed:** sequenced match events from the authoritative server for broadcasters, teams and licensed partners, corrected by new events and tiered by latency; Riot licenses one exclusive distributor (GRID), while Counter-Strike servers stream their match log over HTTP to an address the operator sets ([Esports & Spectating](/books/gaming/esports-and-spectating#official-data-feeds)).
- **Pre-generated, live-generated content:** Steam's content survey categories for AI-made content that ships with a game and content an AI makes while the game runs, the latter needing a description of its guardrails ([AI in Games](/books/gaming/ai-in-games#disclosure-steam-s-content-survey)).
- **Project Chronobreak:** League's esports tool that lets officials rewind a live game to a chosen moment by replaying its Server Network Recording, typically restoring the 40-minute mark in under three minutes ([Esports & Spectating](/books/gaming/esports-and-spectating#replays-rewinds-and-recovery)).
- **Provenance (`asset_provenance`):** a record at import of whether shipped content was made by people, AI or both, with which tool and any performer replica consent, used to answer store surveys ([AI in Games](/books/gaming/ai-in-games#generative-ai-in-production)).
- **Queue time:** from ticket creation to a match, reported as p50, p90 and p99 per queue, region and skill band; FlexMatch separates time to a potential match from time to successful placement ([Game Metrics](/books/gaming/game-metrics#match-quality)).
- **Remote production:** producing a broadcast from a central facility, with venue cameras, observer feeds and audio encoded on site and sent to it ([Esports & Spectating](/books/gaming/esports-and-spectating#broadcast-and-remote-production)).
- **Retention (D1, D7, D30):** the share of an install cohort active exactly N days after its first gameplay day; an unbounded variant counts day N or later ([Game Metrics](/books/gaming/game-metrics#retention-and-cohorts)).
- **Sample ratio mismatch (SRM):** an observed split of players across experiment variants far from the configured one, often caused by a treatment that crashes or breaks logging; a bug alarm before any result is read ([Game Metrics](/books/gaming/game-metrics#experiments)).
- **Server tick health:** the share of server frames that finish within the tick budget, per build and player count; VALORANT reported 99.3% or more since patch 5.07 ([Game Metrics](/books/gaming/game-metrics#technical-health); the numbers are in [Game Servers & Hosting](/books/gaming/game-servers#the-frame-budget-at-128-ticks)).
- **Spectator delay, spectator relay:** the server-side buffer that releases a public spectator stream only after what it shows is stale, and the relay tier that holds keyframes and deltas and fans the stream out without exposing the game server ([Esports & Spectating](/books/gaming/esports-and-spectating#how-to-build-spectating)).
- **StateTree:** Unreal's hierarchical state machine that combines behavior tree selectors with states and transitions ([AI in Games](/books/gaming/ai-in-games#deciding-state-machines-behavior-trees-and-statetree)).
- **Stomp rate:** the share of completed matches decided by a margin above a game-specific threshold (VALORANT's is a win by 8 or more rounds; Call of Duty's Team Deathmatch equivalent is a score delta over 30), read beside queue time ([Game Metrics](/books/gaming/game-metrics#match-quality); VALORANT's smurf figures are in [Matchmaking & Ranked](/books/gaming/matchmaking#new-accounts-and-smurfs)).
- **Tournament license, VRS:** a publisher's permission to run events for its game (Valve's Limited Game Tournament License and above), and the Valve Regional Standings that ranked Counter-Strike 2 events must invite from in order ([Esports & Spectating](/books/gaming/esports-and-spectating#tournament-operations)).
- **Tournament server:** a server local to the players with fixed performance settings on a protected network, trading density for predictability, with pauses and every admin command logged ([Esports & Spectating](/books/gaming/esports-and-spectating#tournament-servers)).
- **Utility AI:** scoring every option from considerations normalized between 0 and 1 and picking the highest, for characters with many competing needs ([AI in Games](/books/gaming/ai-in-games#scoring-utility-ai)).
